# BookVerse — стенд для проверки Менеджера тегов Altcraft

Демонстрационный магазин на GitHub Pages. Нужен, чтобы показать на живом сайте,
что переменные, триггеры и теги Менеджера тегов работают: значения приходят из cookie,
слоя данных и DOM, а запросы пикселя видны в журнале.

Сайт: https://loss2.github.io/bookstore/

## Что на стенде

| Страница | Что делает |
|---|---|
| `index.html` | Каталог. Ссылки «Войти», «Проверка», корзина |
| `auth.html` | Форма входа и регистрации: пишет cookie `bv_email`, `bv_name`, `bv_city` |
| `account.html` | Профиль: показывает cookie, слой данных, корзину и значения переменных |
| `product/index.html` | Карточка товара: класс `add-to-cart`, цена в `#price`, событие `add_to_cart` |
| `checkout.html` | Форма `#checkout`: сумма из корзины, пишет cookie `bv_order_total` и `bv_order_id` |
| `thanks.html` | Страница благодарности: цель `purchase` со суммой из cookie |
| `verify.html` | Проверка переменных: таблица «тип переменной → значение» и кнопки действий |

## Переменные, которые можно проверить

| Тип переменной в контейнере | Настройка | Откуда значение |
|---|---|---|
| Собственный файл cookie | имя `bv_email` | форма входа |
| Собственный файл cookie | имя `bv_city` | форма входа, город доставки |
| Собственный файл cookie | имя `bv_order_total` | оформление заказа |
| Переменная уровня данных | `user_login` → `user_email` | событие входа |
| Переменная уровня данных | `add_to_cart` → `value` | добавление товара |
| Элемент DOM | селектор `#price` | цена на карточке товара |
| Элемент DOM | селектор `#who` | заголовок профиля (email) |
| Константа | `490` | используется в примерах статьи |

## Демонстрация за 5 минут

1. Открыть https://loss2.github.io/bookstore/auth.html, войти под `ivan@example.com`.
2. Открыть https://loss2.github.io/bookstore/account.html — в таблице «Cookie в браузере»
   видно `bv_email=ivan@example.com`, `bv_city=spb`.
3. Открыть `verify.html` — в таблице «Что получит переменная» те же значения.
4. Нажать «Отправить тестовую цель» и посмотреть журнал внизу: строка `пиксель`
   с `match={"email":"ivan@example.com"}` и `update={"_fname":"Иван"}`.
5. В платформе открыть профиль с этим email: цель и поля пришли из переменных, а не из кода страницы.

## Журнал

Панель внизу каждой страницы. Показывает:

- загрузку `actm.js` и `ak_container.js`;
- вызовы `ak_pixel_push` с `match`, `update`, `mmode`, `db_id`;
- фактические запросы пикселя с разобранными параметрами `goals`, `value`, `match`, `update`;
- клики, переходы, ошибки загрузки.

Журнал переживает переход между страницами (хранится в `sessionStorage`).
Клик по заголовку «журнал» сворачивает и разворачивает панель.

## Что нужно настроить в контейнере

Стенд только поставляет данные. Чтобы переменные заработали, в контейнере
`ATM-4ceAGbhFfaZvGHrV7` создаются переменные с настройками из таблицы выше,
а тег цели подставляет их в поля идентификатора и цели.

Проверено на стенде: пиксель инициализируется, `identify` уходит при входе,
`add_to_cart` и `purchase` уходят с суммой из cookie.

Идентификация в примерах идёт по email с `db_id=8` и `mmode=email` — это номер базы,
к которой привязан контейнер `ATM-4ceAGbhFfaZvGHrV7`. Если в вашем контейнере база другая,
поправьте `DB` в `ac-ident.js`.

## Локальный запуск

```bash
python -m http.server 8000
# открыть http://localhost:8000
```

Cookie ставятся на домен, где открыт стенд, поэтому локально и на Pages они независимы.
